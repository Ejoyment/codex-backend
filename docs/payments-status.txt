## Fixed — editor file creation without a workspace

Root cause: onboarding stored a free-text company name on the user but never
created a `Company`; `POST /api/projects` never set `LocalProject.workspaceId`;
and `POST /api/code-editor/files` failed when the user had no company.

Fix:
- `GET /api/company/my-companies` and project/file creation auto-create or reuse
  one personal workspace via `utils/personalWorkspace.js`.
- `POST /api/projects` accepts and validates `workspaceId`, otherwise assigns
  the personal workspace.
- Single and batch file creation use that workspace and attach an orphan
  `LocalProject` to it.
- `company:create` is available on the free tier; the developer tier limit is
  one workspace, so free users can code without upgrading.
- The editor links to `/workspace` for creation; collaboration routes accept a
  company id or slug.

Verified against the `ranger` account: workspace `hud-sonn` was created, file
creation returned 200 without `companyId`, project `son and names` was attached
to it, and `/api/collaboration/hud-sonn/projects` returned 200.

## Fixed

- P1 — Flutterwave checkout no longer trusts client amount/plan.
- P5 — Paystack/Flutterwave verification bound to user, amount, currency, ownership, and card token.
- P6 — Verify and first-charge scheduling are idempotent.
- P7 — `payment-success` verifies provider redirects; Paystack webhook activates trials.
- P8 — Every card-backed trial charges after 14 days, not 10s/210s.
- P9 — One canonical price table for pro/pro_plus/team plans on all rails.
- P12 — Failed Paystack charges enter `past_due`; no immediate downgrade/cancel.
- P13 — Cancellation now keeps the paid tier until period end on both rails.
- P2 / E3 — VFS reads/writes/deletes/metadata are scoped by `_id` + `company`; VFS create rejects foreign companies.
- P3 / E1 — Host debugging is off in production unless `IDE_ALLOW_HOST_EXEC=true`; child processes get an env allowlist instead of `process.env`; debugpy binds to `127.0.0.1`; temp filenames are basenamed.
- P4 / E2 — Production terminal sessions fail closed without VPS transport; a host PTY requires `TERMINAL_ALLOW_HOST_EXEC=true`; boot config warns instead of silently spawning host shells.
- P14 — Legacy `POST /api/subscription/payment/paystack` retired with 410; `/api/paystack-billing/webhook` verifies user, amount, and currency before activation. The canonical `/api/v1/billing/webhook/:provider` path now validates signed activation amount/currency against canonical plan pricing before any entitlement write (including team-tier USD fallback and Stripe pre-tax subtotal). Enterprise remains custom-priced: admin manual provisioning stores the contracted amount and a tamper-evident signature (`POST /api/admin/entitlements/:userId/enterprise`).
- P14 hardening — Admin writes emit a structured `[admin-audit]` line and persist an `AdminAudit` row with a key fingerprint (never the key). Manual entitlement signatures use a dedicated `ENTITLEMENT_SIGNING_SECRET` with comma-separated `ENTITLEMENT_SIGNING_SECRET_PREVIOUS` verification during rotation; `JWT_SECRET` remains a migration fallback. Runbook: `docs/payments-admin-runbook.txt`.
- P11 / E4 — Projects can only be attached to a workspace the caller belongs to; deployments reject a foreign `companyId` or stored project workspace before reading `CodeFile` rows.
- P15 — Deleted dead `utils/paymentRouter.js` and its unused Stripe/Paystack/Flutterwave adapters; no production callers remained.
- E5 (credits) — Agent runs now charge the monthly credit pool atomically across REST, socket, AI-pair agent mode, and follow-up tweaks (1 credit/run by default, `AGENT_JOB_CREDIT_COST`); failures refund, and Pay-As-You-Go may exceed an exhausted pool.
- E5 (compute overage) — Compute overage is recorded on `Subscription.cloudComputeHours` (hours + amount) and reset monthly. New jobs are blocked at/over the included limit unless overage is opted in and below its cap; in-flight jobs record actual overage. Pricing is $1.00/hour (`COMPUTE_OVERAGE_RATE_MINOR_PER_HOUR=100`). Billing is opt-in per subscription (`POST /api/v1/billing/subscription/overage`) and capped at $50/month by default (`COMPUTE_OVERAGE_MONTHLY_CAP_MINOR=5000`); amount accrual stays zero until opt-in, and no invoice/auto-charge path exists yet.
- E9 (backfill) — `POST /api/admin/companies/roles/backfill` repairs missing/invalid roles to `viewer` (dry-run default); owner-only `POST /api/company/:companyId/members/roles/bulk` promotes upward with per-change audit.
- E11 (pub/sub) — `auth:revoke` Redis pub/sub invalidates liveness across instances; `logout-all`/password change/admin ban await publication. Single-device logout remains client-side by design.
- #4 — `config/aiProviders.js` is the single provider registry; router and implementation now expose only gemini, mistral, groq, huggingface, with a test preventing advertised-but-unimplemented providers.

## 2026-10-24 accepted decisions

- E1/E2 — Free tier keeps the VFS/WebContainer terminal and sandboxed Run
  button. Host PTY, unsandboxed host Run fallback, and host debugger are
  paid-only (`terminal:host`, `ide:host`, `debug:host`).
- P13 — User cancellation uses provider period-end semantics. Immediate
  revocation is reserved for abuse/refund handling.
- P15 — Legacy billing routes are instrumented and can be retired with
  `LEGACY_BILLING_RETIRED=true`; provider callbacks bypass the 410.
- E5 — Agent compute hours are metered once per terminal execution for paid
  tiers. Cost-per-hour/pricing is still TBD.
- E10 — Agent execution approvals/rejections share one service across REST and
  socket paths.
- E11 — `tokenVersion` revocation is enforced on REST and socket auth.
- P14 — Enterprise manual provisioning stores the contract amount and a signed
  entitlement.
- E9 — Company roles and collaborator access are explicit; the editor exposes
  per-teammate read/write access.
- Oct 19 #11 — Stuck Paystack/Flutterwave charges are reconciled against the
  provider before being marked complete/failed/manual review.
